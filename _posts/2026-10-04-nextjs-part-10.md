Server Action là cách form nói chuyện với server. Nhưng có những lúc cần một **API HTTP thật**: app mobile gọi lấy danh sách sản phẩm, cổng thanh toán gọi báo "đã trả tiền", đối tác lấy dữ liệu. Đó là **Route Handler**. Bài này viết 3 endpoint, một webhook có kiểm tra chữ ký, và **middleware** chạy trước mọi request.

#### Route Handler là gì
File <mark>route.ts</mark> trong <mark>app/</mark> thay cho <mark>page.tsx</mark>: thư mục đó trả về **dữ liệu** (JSON, ảnh, file) thay vì trang. Mỗi hàm export tên theo HTTP method: <mark>GET</mark>, <mark>POST</mark>, <mark>PUT</mark>, <mark>DELETE</mark>. Nhận <mark>Request</mark> chuẩn web, trả về <mark>Response</mark> chuẩn web. Bài 145 đã dùng một cái cho better-auth mà chưa giải thích.

Khi nào dùng Route Handler thay vì Server Action:

| | Server Action | Route Handler |
|---|---|---|
| Ai gọi | Form và component trong chính app Next.js | Bất kỳ ai: mobile, đối tác, webhook, <mark>fetch</mark> từ trình duyệt |
| URL | Next.js tự sinh, không công khai | Bạn đặt, công khai, có tài liệu |
| Method | Luôn POST | GET/POST/PUT/DELETE tùy ý |
| Cache | Không | GET cache được, kể cả ở CDN |
| Dùng cho | Thay đổi dữ liệu từ giao diện | API công khai, webhook, tải file |

#### Bước 1: API danh sách sản phẩm
```ts
// app/api/products/route.ts
import { NextRequest, NextResponse } from "next/server";
import { prisma } from "@/lib/db";

// GET /api/products?q=apple&page=1
export async function GET(request: NextRequest) {
  const { searchParams } = request.nextUrl;
  const q = searchParams.get("q") ?? "";
  const page = Math.max(1, Number(searchParams.get("page")) || 1);
  const perPage = 6;

  const where = q ? { OR: [{ name: { contains: q } }, { brand: { contains: q } }] } : {};
  const [products, total] = await Promise.all([
    prisma.product.findMany({ where, orderBy: { createdAt: "asc" }, skip: (page - 1) * perPage, take: perPage }),
    prisma.product.count({ where }),
  ]);

  return NextResponse.json(
    { data: products, page, totalPages: Math.ceil(total / perPage), total },
    { headers: { "Cache-Control": "public, s-maxage=60, stale-while-revalidate=300" } }
  );
}
```
Thử
```sh
curl "http://localhost:3000/api/products?q=apple"
```
```json
{"data":[{"id":3,"slug":"watch-series-11","name":"Watch Series 11 GPS 45mm", ...}, {...}],"page":1,"totalPages":1,"total":2}
```
- <mark>NextRequest</mark> là <mark>Request</mark> chuẩn cộng thêm vài tiện ích như <mark>nextUrl.searchParams</mark>. <mark>NextResponse.json()</mark> tạo response JSON với header đúng.
- Phân trang bằng <mark>skip</mark>/<mark>take</mark> của Prisma, kèm <mark>total</mark> để client biết còn trang nào. Query <mark>page</mark> luôn được ép về số và tối thiểu 1.
- Header <mark>Cache-Control</mark>: CDN (Vercel, Cloudflare) cache response 60 giây và trả bản cũ trong lúc làm mới. API đọc dữ liệu ít đổi nên cache; API theo người dùng thì không.

Chi tiết một sản phẩm, với route động như trang:
```ts
// app/api/products/[slug]/route.ts
import { NextResponse } from "next/server";
import { prisma } from "@/lib/db";

export async function GET(_request: Request, { params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params;
  const product = await prisma.product.findUnique({ where: { slug } });

  if (!product) {
    return NextResponse.json({ error: "Không tìm thấy sản phẩm" }, { status: 404 });
  }
  return NextResponse.json(product);
}
```
```sh
curl -i http://localhost:3000/api/products/khong-co
# HTTP/1.1 404 Not Found
# {"error":"Không tìm thấy sản phẩm"}
```
API trả **mã HTTP đúng** (404, không phải 200 kèm chữ "lỗi"), client mới xử lý được. <mark>params</mark> là Promise, như ở trang.

#### Bước 2: Webhook thanh toán
Khi khách trả tiền qua cổng thanh toán (MoMo, VNPay, Stripe...), cổng gọi **vào server của bạn** để báo kết quả. Endpoint đó công khai trên internet, nên phải chắc rằng request **thật sự** đến từ cổng chứ không phải ai đó tự gọi "đơn 1 đã trả tiền". Cách chuẩn là **chữ ký HMAC**: cổng và bạn chia sẻ một secret, cổng ký body bằng secret đó, bạn ký lại và so sánh (bài 093 đã nói về webhook).
```ts
// app/api/webhooks/payment/route.ts
import { createHmac, timingSafeEqual } from "crypto";
import { NextResponse } from "next/server";
import { prisma } from "@/lib/db";

// Cổng thanh toán gọi vào đây khi khách trả tiền xong:
// POST /api/webhooks/payment  body: {"orderId": 1, "status": "paid"}  header: x-signature: <HMAC-SHA256 của body>
export async function POST(request: Request) {
  const rawBody = await request.text(); // phải đọc body dạng chuỗi THÔ để kiểm tra chữ ký
  const signature = request.headers.get("x-signature") ?? "";
  const expected = createHmac("sha256", process.env.PAYMENT_WEBHOOK_SECRET ?? "").update(rawBody).digest("hex");

  const valid =
    signature.length === expected.length && timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
  if (!valid) {
    return NextResponse.json({ error: "Chữ ký không hợp lệ" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody) as { orderId: number; status: string };
  if (payload.status !== "paid") return NextResponse.json({ ok: true, ignored: true });

  // Idempotent: cổng thanh toán có thể gọi lại nhiều lần, chỉ đơn đang "pending" mới được chuyển
  const result = await prisma.order.updateMany({
    where: { id: payload.orderId, status: "pending" },
    data: { status: "paid" },
  });

  return NextResponse.json({ ok: true, updated: result.count });
}
```
Thêm <mark>PAYMENT_WEBHOOK_SECRET="webhook-secret-demo"</mark> vào <mark>.env</mark>, và thêm trạng thái <mark>paid</mark> vào danh sách trạng thái ở bài 145 - 146 (<mark>STATUS_LABEL</mark>, <mark>ORDER_STATUSES</mark>, <mark>select</mark> trong trang admin). Giả làm cổng thanh toán bằng <mark>curl</mark>:
```sh
BODY='{"orderId":1,"status":"paid"}'
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "webhook-secret-demo" | awk '{print $NF}')

# Chữ ký sai
curl -H 'x-signature: abc' -d "$BODY" http://localhost:3000/api/webhooks/payment
# {"error":"Chữ ký không hợp lệ"}   (401)

# Chữ ký đúng
curl -H "x-signature: $SIG" -d "$BODY" http://localhost:3000/api/webhooks/payment
# {"ok":true,"updated":1}

# Gọi lại lần nữa: không đổi gì thêm
curl -H "x-signature: $SIG" -d "$BODY" http://localhost:3000/api/webhooks/payment
# {"ok":true,"updated":0}
```
Ba điểm an toàn trong 25 dòng này:
- Đọc body bằng <mark>request.text()</mark> chứ không <mark>request.json()</mark>: chữ ký tính trên **chuỗi gốc**; parse rồi stringify lại có thể đổi thứ tự key hay khoảng trắng và chữ ký sai.
- <mark>timingSafeEqual</mark> thay vì <mark>===</mark>: so sánh chuỗi thường dừng ở ký tự sai đầu tiên, kẻ tấn công đo thời gian để đoán dần chữ ký. Hàm này luôn mất thời gian như nhau.
- **Idempotent**: cổng thanh toán gọi lại khi không nhận được 200 (mạng lỗi, server restart). <mark>updateMany</mark> với điều kiện <mark>status: "pending"</mark> đảm bảo gọi 10 lần cũng chỉ đổi một lần, cùng kỹ thuật bài 083.

Mỗi cổng thanh toán có cách ký khác nhau (tên header, thuật toán, các field tham gia), nhưng khung xử lý luôn là 3 điểm này.

#### Bước 3: Middleware
Middleware là một hàm chạy **trước mọi request** khớp pattern, ở tầng rất sớm (trước cả render). Việc hợp với nó: chuyển hướng, thêm header, kiểm tra nhanh cookie. Việc **không** hợp: đọc database, logic nghiệp vụ, vì nó chạy trong môi trường hạn chế và chạy cho mọi request.
```ts
// middleware.ts  (ở thư mục gốc, cạnh package.json)
import { NextRequest, NextResponse } from "next/server";

export function middleware(request: NextRequest) {
  // Chặn sớm khu admin khi không có cookie phiên. Kiểm tra quyền thật vẫn nằm ở requireAdmin()
  const hasSession = request.cookies.has("better-auth.session_token");
  if (!hasSession) {
    const loginUrl = new URL("/login", request.url);
    loginUrl.searchParams.set("next", request.nextUrl.pathname);
    return NextResponse.redirect(loginUrl);
  }

  const response = NextResponse.next();
  response.headers.set("X-Frame-Options", "DENY");
  return response;
}

export const config = {
  matcher: ["/admin/:path*", "/orders/:path*"],
};
```
```sh
curl -i http://localhost:3000/admin/orders
# HTTP/1.1 307 Temporary Redirect
# location: http://localhost:3000/login?next=%2Fadmin%2Forders
```
- <mark>matcher</mark> giới hạn middleware chỉ chạy ở <mark>/admin/*</mark> và <mark>/orders/*</mark>. Không có nó, middleware chạy cho cả ảnh, CSS, mọi thứ.
- Middleware chỉ kiểm tra **có cookie hay không**, không xác thực cookie (không gọi database). Nó là lớp lọc rẻ để người chưa đăng nhập bị đẩy đi ngay, kèm <mark>?next=</mark> để sau khi đăng nhập quay lại đúng chỗ (bài tập bài 145). Quyền thật vẫn do <mark>requireAdmin()</mark> quyết định. Đừng bao giờ coi middleware là lớp bảo vệ duy nhất.
- Thêm header bảo mật <mark>X-Frame-Options: DENY</mark> cho khu admin: không ai nhúng trang admin vào iframe để lừa bấm (clickjacking).

Next.js 16 đổi tên file này thành <mark>proxy.ts</mark> với cùng cách hoạt động; nếu bạn dùng 16, chỉ đổi tên file và tên hàm.

#### Bài tập thêm
- <mark>GET /api/orders</mark> trả về đơn của người đang đăng nhập (đọc phiên bằng <mark>auth.api.getSession({ headers: request.headers })</mark>), 401 nếu chưa đăng nhập.
- Thêm rate limit đơn giản cho webhook: đếm số request theo IP trong 1 phút bằng một <mark>Map</mark> trong bộ nhớ (đủ cho một server; nhiều server thì dùng Redis, bài 086).
- Số sản phẩm trong giỏ ở header: Route Handler <mark>GET /api/cart/count</mark> đọc cookie, và một Client Component gọi nó bằng <mark>fetch</mark> sau khi trang hiện (cách giữ layout tĩnh đã bàn ở bài 143).
