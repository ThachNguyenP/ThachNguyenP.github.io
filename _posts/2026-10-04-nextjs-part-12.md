Bài cuối: đưa TechShop lên internet. Ba việc: thay SQLite bằng PostgreSQL (SQLite là file trên đĩa, không hợp với server có nhiều bản chạy), đưa mọi cấu hình bí mật ra biến môi trường, và deploy bằng một trong hai cách: **Vercel** (đơn giản nhất cho Next.js) hoặc **Docker** (chạy ở bất kỳ đâu). Cả hai cách tôi đều chạy thật trước khi viết.

#### Bước 1: Biến môi trường
Tới giờ <mark>.env</mark> có 5 biến. Tạo file <mark>.env.example</mark> liệt kê chúng (không có giá trị thật) và **commit file này**, để ai clone về biết cần điền gì:
```
# Copy thành .env và điền giá trị thật. Không commit .env
DATABASE_URL="postgresql://postgres:techshop@localhost:5434/techshop"
BETTER_AUTH_SECRET="tao-bang-lenh: openssl rand -base64 32"
BETTER_AUTH_URL="http://localhost:3000"
NEXT_PUBLIC_SITE_URL="http://localhost:3000"
PAYMENT_WEBHOOK_SECRET="doi-thanh-secret-do-cong-thanh-toan-cap"
```
Quy tắc: biến **không** có tiền tố <mark>NEXT_PUBLIC_</mark> chỉ tồn tại trên server, <mark>process.env.DATABASE_URL</mark> trong Client Component là <mark>undefined</mark>. Biến có <mark>NEXT_PUBLIC_</mark> được **nhúng vào JavaScript lúc build** và ai cũng đọc được; chỉ đặt những thứ công khai (domain, key public của analytics). Lên production, mỗi biến có giá trị riêng: <mark>BETTER_AUTH_URL</mark> và <mark>NEXT_PUBLIC_SITE_URL</mark> là <mark>https://techshop.vn</mark>, secret là chuỗi ngẫu nhiên mới.

#### Bước 2: PostgreSQL
Chạy Postgres bằng Docker ngay trên máy (hoặc tạo database miễn phí ở Neon, Supabase và lấy connection string):
```sh
docker run -d --name techshop-db -p 5434:5432 -e POSTGRES_PASSWORD=techshop -e POSTGRES_DB=techshop postgres:17-alpine
```
Đổi provider ở hai chỗ
```prisma
// prisma/schema.prisma (phần datasource)
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}
```
```ts
// lib/auth.ts (đổi provider)
database: prismaAdapter(prisma, { provider: "postgresql" }),
```
Và <mark>DATABASE_URL="postgresql://postgres:techshop@localhost:5434/techshop"</mark> trong <mark>.env</mark>.

Các file migration cũ là SQL của SQLite (<mark>AUTOINCREMENT</mark>, <mark>DATETIME</mark>), Postgres không hiểu. Xóa thư mục <mark>prisma/migrations</mark> và tạo lại từ schema:
```sh
rm -rf prisma/migrations
npx prisma migrate dev --name init
npx prisma db seed
npx tsx prisma/make-admin.ts thach@example.com
```
Dữ liệu SQLite cũ không chuyển sang (với dự án đang học thì không cần; dự án thật thì đổi database ngay từ đầu, hoặc dùng <mark>pg_dump</mark>/script chuyển dữ liệu).

Một khác biệt nhỏ đã nhắc ở bài 142: tìm kiếm <mark>contains</mark> trên Postgres phân biệt hoa thường. Thêm <mark>mode: "insensitive"</mark> ở <mark>lib/products.ts</mark> và <mark>app/api/products/route.ts</mark>:
```ts
{ OR: [{ name: { contains: query, mode: "insensitive" as const } }, { brand: { contains: query, mode: "insensitive" as const } }] }
```
(<mark>as const</mark> để TypeScript hiểu đây là giá trị cố định, không phải chuỗi bất kỳ; thiếu nó build báo lỗi kiểu.)

Chạy <mark>npm run dev</mark>, mọi thứ như cũ nhưng dữ liệu trong Postgres. Đổi database mà không sửa trang nào: đó là lợi ích của việc gói truy cập dữ liệu vào <mark>lib/</mark> và dùng ORM.

#### Bước 3: Health check
Mọi nền tảng deploy đều cần một URL để kiểm tra app còn sống:
```ts
// app/api/health/route.ts  —  cho load balancer / uptime monitor kiểm tra app còn sống
import { NextResponse } from "next/server";
import { prisma } from "@/lib/db";

export async function GET() {
  try {
    await prisma.$queryRaw`SELECT 1`;
    return NextResponse.json({ ok: true });
  } catch {
    return NextResponse.json({ ok: false, error: "database unreachable" }, { status: 503 });
  }
}
```
Trả 503 khi mất database để load balancer ngừng đẩy traffic vào bản bị lỗi.

#### Cách 1: Vercel
Vercel là công ty làm ra Next.js, deploy gần như không cần cấu hình:
1. Đẩy code lên GitHub (chắc chắn <mark>.env</mark> không được commit, <mark>.gitignore</mark> đã lo).
2. Tạo database Postgres ở **Neon** (neon.tech, có gói miễn phí), copy connection string.
3. Vào vercel.com → Add New Project → chọn repo. Ở mục Environment Variables, nhập 5 biến với giá trị production. <mark>BETTER_AUTH_URL</mark> và <mark>NEXT_PUBLIC_SITE_URL</mark> là domain Vercel cấp (<mark>https://techshop.vercel.app</mark>), sau có domain riêng thì đổi.
4. Sửa script build để migration chạy trước mỗi lần deploy: trong <mark>package.json</mark>, <mark>"build": "prisma migrate deploy && next build --turbopack"</mark>.
5. Bấm Deploy. Khoảng 2 phút sau có link.

<mark>prisma migrate deploy</mark> khác <mark>migrate dev</mark>: chỉ **áp dụng** migration có sẵn, không tạo mới, không reset. Đây là lệnh duy nhất được chạy ở production. Mỗi lần push lên <mark>main</mark>, Vercel tự build và deploy lại; push lên nhánh khác thì có link preview riêng để xem thử.

Lúc build, các trang tĩnh (trang chủ, 8 trang sản phẩm) được tạo bằng cách đọc database production, nên <mark>DATABASE_URL</mark> phải đúng ngay từ lúc build, không chỉ lúc chạy.

#### Cách 2: Docker
Khi deploy lên VPS của bạn, hoặc nền tảng khác (Railway, Render, Fly.io, AWS). Bật chế độ **standalone**: Next.js gom đúng những file cần để chạy vào một thư mục, không cần cả <mark>node_modules</mark> khổng lồ:
```ts
// next.config.ts
import type { NextConfig } from "next";

const nextConfig: NextConfig = {
  output: "standalone", // build ra thư mục tự chạy, dùng cho Docker (bài 149)
  // Đảm bảo engine của Prisma được copy vào thư mục standalone
  outputFileTracingIncludes: { "/**/*": ["./node_modules/.prisma/client/**/*"] },
};

export default nextConfig;
```
Dòng <mark>outputFileTracingIncludes</mark> giải quyết một lỗi rất hay gặp: Prisma có một file engine nhị phân mà Next.js không tự phát hiện, thiếu nó container khởi động rồi sập với "Query engine not found".
```dockerfile
# Dockerfile — build 3 tầng: cài thư viện, build, chạy
FROM node:20-alpine AS base
RUN apk add --no-cache libc6-compat openssl

# 1. Cài đúng phiên bản trong package-lock
FROM base AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# 1b. Ảnh nhỏ chỉ để chạy migration: docker compose run --rm migrate
FROM deps AS migrate
WORKDIR /app
COPY prisma ./prisma
COPY prisma.config.ts ./
CMD ["npx", "prisma", "migrate", "deploy"]

# 2. Build. Cần DATABASE_URL vì các trang tĩnh đọc database lúc build (bài 141)
FROM base AS builder
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
ARG DATABASE_URL
ARG BETTER_AUTH_SECRET
ENV DATABASE_URL=$DATABASE_URL BETTER_AUTH_SECRET=$BETTER_AUTH_SECRET NEXT_TELEMETRY_DISABLED=1
RUN npx prisma generate && npm run build

# 3. Ảnh chạy: chỉ chứa thư mục standalone, nhỏ và không có devDependencies
FROM base AS runner
WORKDIR /app
ENV NODE_ENV=production PORT=3000 HOSTNAME=0.0.0.0
RUN addgroup -S nodejs && adduser -S nextjs -G nodejs
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static
USER nextjs
EXPOSE 3000
CMD ["node", "server.js"]
```
```
# .dockerignore
node_modules
.next
.git
.env
*.db
```
Dockerfile nhiều tầng (multi-stage): tầng cuối chỉ copy kết quả build, nên ảnh chạy chỉ **307MB** thay vì hơn 1GB nếu copy cả <mark>node_modules</mark>. App chạy bằng user <mark>nextjs</mark> không có quyền root. Series Docker trước đây (bài 029 - 031) có giải thích kỹ từng lệnh.

File compose chạy cả database, migration và app:
```yaml
# docker-compose.yml — chạy cả database và app bằng một lệnh
services:
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_PASSWORD: techshop
      POSTGRES_DB: techshop
    ports:
      - "5434:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

  # Chạy migration rồi thoát: docker compose run --rm migrate
  migrate:
    build:
      context: .
      target: migrate
    environment:
      DATABASE_URL: postgresql://postgres:techshop@db:5432/techshop
    depends_on:
      db:
        condition: service_healthy

  web:
    build:
      context: .
      args:
        DATABASE_URL: postgresql://postgres:techshop@host.docker.internal:5434/techshop
        BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET}
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgresql://postgres:techshop@db:5432/techshop
      BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET}
      BETTER_AUTH_URL: http://localhost:3000
      NEXT_PUBLIC_SITE_URL: http://localhost:3000
      PAYMENT_WEBHOOK_SECRET: ${PAYMENT_WEBHOOK_SECRET}
    depends_on:
      db:
        condition: service_healthy

volumes:
  pgdata:
```
Thứ tự chạy, đúng như tôi đã làm:
```sh
export BETTER_AUTH_SECRET="..." PAYMENT_WEBHOOK_SECRET="..."
docker compose up -d db              # 1. database
docker compose run --rm migrate      # 2. tạo bảng: "No pending migrations to apply" nếu đã có
docker compose build web             # 3. build ảnh, vài phút lần đầu
docker compose up -d web             # 4. chạy
curl http://localhost:3000/api/health   # {"ok":true}
```
Hai điểm lạ trong file compose, cố ý:
- <mark>web</mark> có **hai** <mark>DATABASE_URL</mark>: <mark>args</mark> dùng lúc **build** (chạy trên máy bạn, nên tới Postgres qua <mark>host.docker.internal:5434</mark>, tức cổng đã map ra máy), <mark>environment</mark> dùng lúc **chạy** (trong mạng của compose, tới thẳng service <mark>db:5432</mark>). Trên Linux, <mark>host.docker.internal</mark> cần thêm <mark>extra_hosts: ["host.docker.internal:host-gateway"]</mark>.
- Migration là service riêng chạy xong thì thoát, không nằm trong lệnh khởi động của <mark>web</mark>: nếu chạy 3 bản <mark>web</mark> cùng lúc, cả 3 sẽ tranh nhau migrate.

Lên VPS: cài Docker, clone code, điền <mark>.env</mark>, chạy đúng 4 lệnh trên, rồi đặt Nginx hoặc Caddy phía trước để có HTTPS cho domain.

#### Checklist trước khi mở cho khách
- <mark>npm run build</mark> trên máy không có warning; <mark>npm run lint</mark> sạch.
- <mark>BETTER_AUTH_SECRET</mark> production khác development và dài ít nhất 32 ký tự.
- <mark>NEXT_PUBLIC_SITE_URL</mark> là domain thật: ảnh OG, sitemap, robots đều dùng nó.
- Mở <mark>/api/health</mark> trên production: <mark>{"ok":true}</mark>. Mở <mark>/admin</mark> khi chưa đăng nhập: về <mark>/login</mark>.
- Đăng ký tài khoản thật, chạy <mark>make-admin</mark> trên database production (qua <mark>docker compose run --rm migrate npx tsx prisma/make-admin.ts email</mark>, hoặc sửa cột <mark>role</mark> bằng công cụ của Neon).
- Nộp <mark>/sitemap.xml</mark> vào Google Search Console; dán link sản phẩm vào Facebook debugger xem ảnh OG.
- Bật backup database (Neon tự làm; VPS thì <mark>pg_dump</mark> hằng ngày bằng cron).
