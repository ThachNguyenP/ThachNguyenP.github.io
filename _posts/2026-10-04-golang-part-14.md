Bài cuối: đưa Pulse lên một máy chủ thật. Go có một lợi thế mà Ruby hay Node không có: kết quả build là **một file binary duy nhất**, không cần cài runtime, không cần <mark>node_modules</mark> hay <mark>bundle install</mark> trên server. Nhờ vậy có hai cách deploy đều gọn: Docker Compose (app + PostgreSQL + Redis trên một VPS), hoặc chép binary lên và chạy bằng systemd. Cả hai tôi đều chạy thật trước khi viết. Cuối bài là bảng nhìn lại 14 bài và những gì nên học tiếp.

#### Bước 1: Phiên bản gắn vào binary
Khi có sự cố, câu hỏi đầu tiên là "server đang chạy bản nào?". Go cho phép **gán giá trị cho biến lúc build** qua linker flag <mark>-X</mark>:
```go
// cmd/pulsed/main.go (thêm, trước func main)
// version được gán lúc build: go build -ldflags="-X main.version=1.2.3"
var version = "dev"
```
Chạy <mark>go run</mark> thì <mark>version</mark> là <mark>"dev"</mark>; build với <mark>-ldflags="-X main.version=1.2.3"</mark> thì linker ghi đè thành <mark>"1.2.3"</mark>, code không phải đổi. Ghi version vào log lúc khởi động và trả trong <mark>/healthz</mark>:
```go
// cmd/pulsed/main.go (thêm trong run, sau setupLogger)
	slog.Info("pulsed khởi động", "version", version)
```
```go
// internal/api/server.go (sửa: thêm trường Version vào Deps và Server, healthz trả nó)
	writeJSON(w, http.StatusOK, map[string]string{"status": "ok", "version": s.version})
```
(Thêm <mark>Version string</mark> vào <mark>Deps</mark>, <mark>version string</mark> vào <mark>Server</mark>, copy trong <mark>New</mark>, và <mark>Version: version</mark> ở chỗ gọi <mark>api.New</mark> trong main.) Giờ <mark>curl /healthz</mark> trên production cho biết ngay bản đang chạy.

#### Bước 2: Makefile build và cross-compile
```makefile
# Makefile
VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
LDFLAGS  = -s -w -X main.version=$(VERSION)

.PHONY: run fakeweb test test-db lint build release docker

run:            ## chạy server
	go run ./cmd/pulsed

fakeweb:        ## web giả để thử
	go run ./cmd/fakeweb

test:           ## test nhanh, không cần database
	go test -race ./...

test-db:        ## test cả store với PostgreSQL thật
	TEST_DATABASE_URL=postgres://pulse:pulse@localhost:5432/pulse_test?sslmode=disable go test -race -cover ./...

lint:           ## kiểm tra định dạng và lỗi tĩnh
	gofmt -l . && go vet ./...

build:          ## build binary cho máy này
	go build -ldflags="$(LDFLAGS)" -o bin/pulsed ./cmd/pulsed

release:        ## build cho máy chủ Linux (VPS phổ biến là amd64)
	CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="$(LDFLAGS)" -o bin/pulsed-linux-amd64 ./cmd/pulsed
	CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -ldflags="$(LDFLAGS)" -o bin/pulsed-linux-arm64 ./cmd/pulsed

docker:         ## build Docker image
	docker build --build-arg VERSION=$(VERSION) -t pulse:$(VERSION) .
```
Ba thứ mới trong flag build:
- <mark>-s -w</mark>: bỏ bảng ký hiệu và thông tin debug, binary nhỏ đi khoảng 30%. Stack trace khi panic vẫn có tên hàm và số dòng, chỉ mất khả năng gắn debugger.
- <mark>VERSION</mark> lấy từ <mark>git describe</mark>: tag gần nhất (ví dụ <mark>v1.0.0</mark>), hoặc hash commit, thêm <mark>-dirty</mark> nếu có file chưa commit. Không có git (trong zip tải về) thì rơi về <mark>dev</mark>.
- <mark>GOOS=linux GOARCH=amd64</mark>: **cross-compile**. Từ máy Mac (arm64) build thẳng ra binary chạy trên server Linux Intel, không cần Docker, không cần máy ảo. Với Ruby hay Node, bạn phải cài đúng runtime và cài lại dependency trên server; với Go, mọi thứ đã nằm trong file. <mark>CGO_ENABLED=0</mark> tắt việc gọi code C, kết quả là binary **tĩnh** không phụ thuộc thư viện nào của hệ điều hành (quan trọng ở bước 4).

Thêm <mark>/bin/</mark> vào <mark>.gitignore</mark> rồi chạy:
```sh
make release
file bin/pulsed-linux-amd64
# bin/pulsed-linux-amd64: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked
ls -la bin/
# pulsed              24.3MB  (mac arm64)
# pulsed-linux-amd64  25.9MB
# pulsed-linux-arm64  24.0MB
```
24MB cho cả HTTP server, driver PostgreSQL, Redis, JWT, Prometheus client và template HTML. Đó là toàn bộ thứ cần chép lên server.

#### Bước 3: Lệnh healthcheck
Docker có <mark>HEALTHCHECK</mark> để biết container còn sống; thường người ta dùng <mark>curl localhost:3000/healthz</mark>. Nhưng image ở bước 4 **không có curl, không có shell**. Giải pháp: dạy chính pulsed tự kiểm tra mình:
```go
// cmd/pulsed/main.go (thêm vào đầu main và hàm mới ở cuối file)
func main() {
	// `pulsed healthcheck` dùng cho HEALTHCHECK của Docker: image distroless không có curl.
	if len(os.Args) > 1 && os.Args[1] == "healthcheck" {
		os.Exit(healthcheck())
	}
	...
}

// healthcheck gọi /healthz của chính mình, trả 0 nếu ổn, 1 nếu không.
func healthcheck() int {
	addr := os.Getenv("ADDR")
	if addr == "" {
		addr = ":3000"
	}
	client := http.Client{Timeout: 3 * time.Second}
	resp, err := client.Get("http://127.0.0.1" + addr + "/healthz")
	if err != nil || resp.StatusCode != http.StatusOK {
		return 1
	}
	resp.Body.Close()
	return 0
}
```
<mark>pulsed healthcheck</mark> là một **subcommand** thô sơ: nhìn <mark>os.Args[1]</mark> rồi rẽ nhánh. Dự án CLI lớn dùng thư viện cobra cho việc này, nhưng một <mark>if</mark> là đủ. Mã thoát 0 là "khỏe", khác 0 là "bệnh", đúng quy ước Unix mà Docker và systemd đều hiểu. Thử khi server chưa chạy: <mark>./bin/pulsed healthcheck; echo $?</mark> in <mark>1</mark>.

#### Bước 4: Dockerfile hai giai đoạn
```dockerfile
# Dockerfile
# ---- Giai đoạn 1: build ----
FROM golang:1.26-alpine AS build
WORKDIR /src

# Tải thư viện trước, để sửa code không phải tải lại (tận dụng cache của Docker).
COPY go.mod go.sum ./
RUN go mod download

COPY . .
ARG VERSION=dev
# CGO_ENABLED=0: binary tĩnh, không cần thư viện C của hệ điều hành.
# -s -w: bỏ bảng debug, binary nhỏ hơn khoảng 30%.
RUN CGO_ENABLED=0 go build -ldflags="-s -w -X main.version=${VERSION}" -o /pulsed ./cmd/pulsed

# ---- Giai đoạn 2: chạy ----
# distroless: không shell, không package manager, chỉ có binary + CA certs + tzdata.
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /pulsed /pulsed
EXPOSE 3000
ENTRYPOINT ["/pulsed"]
```
```
# .dockerignore
.git
.env
*.md
/pulse
/pulsed
deploy/
```
So với Dockerfile của Next.js ở bài 149 (ba tầng, 307MB), bản này đơn giản hơn nhiều vì giai đoạn chạy chỉ cần **một file**:
- Giai đoạn build dùng image Go đầy đủ (vài trăm MB). Copy <mark>go.mod</mark> và <mark>go.sum</mark> trước rồi <mark>go mod download</mark>: layer này chỉ build lại khi dependency đổi, còn sửa code thì Docker dùng cache, build nhanh hơn nhiều.
- Giai đoạn chạy dùng **distroless** của Google: image không có shell, không có <mark>apt</mark>, không có gì ngoài CA certificates, tzdata và user <mark>nonroot</mark>. Không shell nghĩa là kẻ tấn công có vào được cũng không có gì để chạy. Bản <mark>static</mark> dùng được vì binary của ta tĩnh (<mark>CGO_ENABLED=0</mark>).
- CA certificates là bắt buộc: checker gọi HTTPS tới website của khách, không có CA thì mọi check đều "certificate signed by unknown authority". tzdata để <mark>time.LoadLocation</mark> và định dạng giờ địa phương trên trang status chạy đúng. Hai thứ này rất hay bị quên khi người ta dùng image <mark>scratch</mark> trống hoàn toàn.
- Tag <mark>:nonroot</mark> chạy app bằng user thường, không phải root.

Lần build đầu tiên của tôi thất bại:
```
go: go.mod requires go >= 1.26.0 (running go 1.25.14; GOTOOLCHAIN=local)
```
Cách đọc: <mark>go.mod</mark> khai báo <mark>go 1.26.0</mark> (các thư viện ta dùng yêu cầu vậy), còn image build lúc đó là <mark>golang:1.25-alpine</mark>. Image build phải **bằng hoặc mới hơn** dòng <mark>go</mark> trong <mark>go.mod</mark>. Sửa thành <mark>golang:1.26-alpine</mark> là xong. Khi bạn nâng go.mod, nhớ nâng Dockerfile và CI (<mark>go-version-file: go.mod</mark> ở bài 12 tự lo chuyện này).
```sh
make docker
docker images pulse
# pulse  0.1.0  25.6MB
```
Image 25.6MB, gần bằng binary. Chạy thử nối vào PostgreSQL và Redis trên máy host:
```sh
docker run --rm -p 3001:3000 \
  -e DATABASE_URL=postgres://pulse:pulse@host.docker.internal:5432/pulse?sslmode=disable \
  -e REDIS_URL=redis://host.docker.internal:6379/0 \
  -e JWT_SECRET=... -e LOG_FORMAT=json pulse:0.1.0
```
```
{"time":"2026-11-04T16:43:11.909970291Z","level":"INFO","msg":"pulsed khởi động","version":"0.1.0"}
{"time":"2026-11-04T16:43:11.933339708Z","level":"INFO","msg":"database sẵn sàng"}
```
<mark>curl localhost:3001/healthz</mark> trả <mark>{"status":"ok","version":"0.1.0"}</mark>, và <mark>docker exec <container> /pulsed healthcheck</mark> thoát với mã 0. Để ý giờ trong log là UTC (<mark>Z</mark>): container không có <mark>TZ</mark>, log theo UTC là chuyện bình thường và thậm chí nên thế khi server ở nhiều múi giờ.

#### Bước 5: Cách A, Docker Compose trên VPS
File compose cho production khác file dev ở bài 6: app cũng chạy trong Docker, mật khẩu không hardcode, có restart và healthcheck:
```yaml
# docker-compose.prod.yml
# Chạy toàn bộ Pulse trên một máy chủ: docker compose -f docker-compose.prod.yml up -d
services:
  app:
    build:
      context: .
      args:
        VERSION: ${VERSION:-dev}
    image: pulse:${VERSION:-dev}
    restart: unless-stopped
    env_file: .env
    environment:
      DATABASE_URL: postgres://pulse:${POSTGRES_PASSWORD}@postgres:5432/pulse?sslmode=disable
      REDIS_URL: redis://redis:6379/0
      LOG_FORMAT: json
    ports:
      - "127.0.0.1:3000:3000"
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_started
    healthcheck:
      test: ["/pulsed", "healthcheck"]
      interval: 30s
      timeout: 5s
      retries: 3

  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: pulse
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: pulse
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U pulse"]
      interval: 5s
      timeout: 5s
      retries: 10

  redis:
    image: redis:7-alpine
    restart: unless-stopped

volumes:
  pgdata:
```
Đọc từng ý:
- <mark>env_file: .env</mark> nạp JWT_SECRET, TELEGRAM_*, WORKERS... còn <mark>environment</mark> ghi đè ba biến phụ thuộc vào mạng của compose: hostname <mark>postgres</mark> và <mark>redis</mark> là tên service, Docker tự phân giải.
- <mark>ports: "127.0.0.1:3000:3000"</mark>: chỉ máy chủ gọi được cổng 3000, Internet thì không. Phía trước sẽ là Caddy lo HTTPS (bước 7). Postgres và Redis không mở cổng nào ra ngoài.
- <mark>depends_on</mark> với <mark>condition: service_healthy</mark>: app chỉ khởi động sau khi <mark>pg_isready</mark> báo ổn; không có nó, app chạy trước Postgres và chết ngay với "connection refused" (dù <mark>restart</mark> sẽ cứu, log vẫn bẩn).
- <mark>healthcheck</mark> của app dùng lệnh ở bước 3. Container "unhealthy" thì <mark>docker ps</mark> hiện rõ và Compose có thể restart.
- <mark>restart: unless-stopped</mark>: server reboot thì mọi thứ tự lên.

Trên VPS (Ubuntu, đã cài Docker): clone code, tạo <mark>.env</mark> theo bảng ở bước 8, rồi
```sh
POSTGRES_PASSWORD=$(openssl rand -hex 16) VERSION=1.0.0 \
  docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml logs -f app
```
(Đặt <mark>POSTGRES_PASSWORD</mark> và <mark>VERSION</mark> vào <mark>.env</mark> luôn để khỏi gõ lại; Compose đọc <mark>.env</mark> cho cả biến <mark>${...}</mark> trong file yaml.) Migration **tự chạy lúc khởi động** nhờ <mark>db.Migrate</mark> ở bài 6, nên không có bước migrate riêng như Next.js ở bài 149. Cập nhật phiên bản mới: <mark>git pull</mark>, đổi <mark>VERSION</mark>, chạy lại đúng lệnh <mark>up -d --build</mark>; Compose build image mới và thay container, mất vài giây gián đoạn. Lúc thay, container cũ nhận SIGTERM và graceful shutdown ở bài 5 làm việc: request dở dang được trả xong, scheduler chờ check đang chạy lưu xong rồi mới thoát.

Backup database, việc không ai nhớ cho tới khi mất dữ liệu:
```sh
docker compose -f docker-compose.prod.yml exec postgres pg_dump -U pulse pulse > backup-$(date +%F).sql
```
Đặt vào cron mỗi đêm và chép file đi nơi khác (S3, máy khác).

#### Bước 6: Cách B, binary + systemd
Không muốn Docker? Chép binary lên và để systemd (trình quản lý dịch vụ của Linux) chạy nó. Postgres và Redis cài bằng <mark>apt</mark> hoặc dùng dịch vụ có sẵn.
```sh
make release
ssh server 'sudo useradd -r -s /usr/sbin/nologin pulse; sudo mkdir -p /opt/pulse'
scp bin/pulsed-linux-amd64 server:/tmp/pulsed
scp .env.production server:/tmp/.env
ssh server 'sudo mv /tmp/pulsed /opt/pulse/pulsed && sudo mv /tmp/.env /opt/pulse/.env \
  && sudo chown -R pulse:pulse /opt/pulse && sudo chmod 600 /opt/pulse/.env'
```
```ini
# deploy/pulsed.service
# Chạy pulsed như một dịch vụ hệ thống (không Docker): /etc/systemd/system/pulsed.service
[Unit]
Description=Pulse uptime monitor
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
User=pulse
Group=pulse
WorkingDirectory=/opt/pulse
EnvironmentFile=/opt/pulse/.env
ExecStart=/opt/pulse/pulsed
Restart=always
RestartSec=3
# Khi tắt, systemd gửi SIGTERM; pulsed có 15 giây để xong request dở dang.
KillSignal=SIGTERM
TimeoutStopSec=15

# Vài rào chắn bảo mật cơ bản
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/opt/pulse

[Install]
WantedBy=multi-user.target
```
- <mark>EnvironmentFile</mark> đọc <mark>.env</mark> thành biến môi trường; <mark>config.Load</mark> không cần biết là systemd hay Docker.
- <mark>KillSignal=SIGTERM</mark> và <mark>TimeoutStopSec=15</mark> khớp với <mark>signal.NotifyContext(..., syscall.SIGTERM)</mark> ở bài 5: systemd gửi SIGTERM, pulsed có tối đa 15 giây (ta đặt 10 giây cho <mark>Shutdown</mark>) để xong việc, quá hạn mới bị SIGKILL.
- <mark>ProtectSystem=strict</mark> làm cả hệ thống file thành chỉ đọc với tiến trình này, trừ <mark>/opt/pulse</mark>. Pulse không ghi file nào nên hoàn toàn ổn, và nếu có lỗ hổng, kẻ tấn công không sửa được gì.

Kích hoạt:
```sh
sudo cp deploy/pulsed.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pulsed
sudo journalctl -u pulsed -f          # xem log (stdout của app được journald gom)
```
Cập nhật bản mới: <mark>scp</mark> binary mới đè lên, <mark>sudo systemctl restart pulsed</mark>. Vì chỉ có một file, rollback là chép lại file cũ.

#### Bước 7: HTTPS với Caddy
Cả hai cách đều để app ở <mark>127.0.0.1:3000</mark>. Caddy đứng trước, tự xin chứng chỉ Let's Encrypt và tự gia hạn, cấu hình đúng ba dòng:
```
# deploy/Caddyfile
# Caddy tự xin và gia hạn chứng chỉ HTTPS từ Let's Encrypt. /etc/caddy/Caddyfile
pulse.example.com {
    reverse_proxy 127.0.0.1:3000
}
```
Trỏ DNS của domain về IP server, <mark>sudo apt install caddy</mark>, chép file vào <mark>/etc/caddy/Caddyfile</mark>, <mark>sudo systemctl reload caddy</mark>. Caddy tự thêm header <mark>X-Forwarded-For</mark> với IP thật của khách; bài 10 đã nhắc: lúc này hàm <mark>clientIP</mark> nên đọc header đó (bài tập 2).

#### Bước 8: Biến môi trường trên production
| Biến | Giá trị production | Ghi chú |
|---|---|---|
| <mark>JWT_SECRET</mark> | <mark>openssl rand -hex 32</mark> | Đổi là mọi token cũ hết hạn ngay |
| <mark>DATABASE_URL</mark> | tới Postgres thật | Compose tự điền |
| <mark>REDIS_URL</mark> | tới Redis thật | Để trống thì mất cache và rate limit |
| <mark>LOG_FORMAT</mark> | <mark>json</mark> | |
| <mark>LOG_LEVEL</mark> | <mark>info</mark> | <mark>debug</mark> khi đang truy lỗi |
| <mark>DEBUG_ADDR</mark> | <mark>127.0.0.1:6060</mark> hoặc trống | Không bao giờ <mark>0.0.0.0</mark> |
| <mark>WORKERS</mark> | 10 - 50 | Tùy số monitor và CPU |
| <mark>DOWN_THRESHOLD</mark> | 3 | 2 nếu interval dài |
| <mark>TELEGRAM_BOT_TOKEN</mark>, <mark>TELEGRAM_CHAT_ID</mark>, <mark>WEBHOOK_URL</mark> | kênh thật | |

<mark>.env</mark> trên server có quyền <mark>600</mark>, không nằm trong git, không nằm trong image (<mark>.dockerignore</mark> đã loại).

#### Mẹo và lỗi hay gặp
- **"certificate signed by unknown authority"** cho mọi check: image thiếu CA certificates. Distroless <mark>static</mark> có sẵn; nếu bạn đổi sang <mark>scratch</mark> phải tự copy <mark>/etc/ssl/certs</mark> từ giai đoạn build.
- **Chạy hai bản pulsed** (để không gián đoạn khi deploy, hoặc chịu tải): hoàn toàn được. <mark>FOR UPDATE SKIP LOCKED</mark> ở bài 7 bảo đảm hai bản không kiểm tra trùng monitor, rate limit ở bài 10 đếm chung trong Redis. Caddy có thể cân bằng tải giữa hai cổng. Đây là bước lên "zero-downtime deploy".
- **Binary build trên Mac không chạy trên server**: "cannot execute binary file". Bạn chép nhầm <mark>bin/pulsed</mark> (arm64 cho Mac) thay vì <mark>bin/pulsed-linux-amd64</mark>. Kiểm tra bằng <mark>file</mark>.
- **Git describe ra <mark>-dirty</mark>** trong tên image: có file chưa commit. Commit trước khi build release để version truy ngược được về đúng commit.
- Chỉ mở cổng 80, 443 (và 22) trên firewall của VPS. Cổng 3000, 5432, 6379, 6060 đều chỉ loopback hoặc mạng nội bộ của Docker.

#### Checklist
- <mark>make release</mark> ra hai binary Linux; <mark>file</mark> báo <mark>statically linked</mark>.
- <mark>make docker</mark> ra image khoảng 25MB; <mark>docker run</mark> rồi <mark>curl /healthz</mark> thấy đúng version.
- <mark>docker compose -f docker-compose.prod.yml up -d --build</mark> trên VPS: <mark>docker ps</mark> hiện app <mark>healthy</mark>.
- Hoặc: <mark>systemctl status pulsed</mark> là <mark>active (running)</mark>, <mark>journalctl -u pulsed</mark> có dòng "pulsed khởi động".
- <mark>https://pulse.example.com/healthz</mark> qua Caddy trả JSON, chứng chỉ hợp lệ.
- Đăng ký tài khoản thật, tạo monitor cho website của bạn, tắt website vài phút và nhận được tin Telegram.

#### Bài tập thêm
1. Làm <mark>clientIP</mark> đọc <mark>X-Forwarded-For</mark> khi biến <mark>TRUST_PROXY=true</mark>, để rate limit tính theo IP thật của khách thay vì IP của Caddy.
2. Thêm job vào CI của bài 12: khi push tag <mark>v*</mark>, build image, đẩy lên GitHub Container Registry với tag là version. Server chỉ cần <mark>docker compose pull && up -d</mark>.
3. Viết script backup chạy bằng cron, giữ 7 bản gần nhất, và thử **restore** vào một database trống. Backup chưa restore thử thì chưa phải backup.
4. Chạy hai bản app trong compose (<mark>deploy: replicas: 2</mark>) sau Caddy, deploy bản mới và quan sát không có request nào lỗi.
