REST hay GraphQL thường dùng cho FE, Mobile gọi vào backend. Còn khi các service backend gọi lẫn nhau (microservices), <mark>gRPC</mark> là một lựa chọn rất phổ biến.

#### gRPC là gì
- **RPC** (Remote Procedure Call): gọi một hàm ở server khác giống như gọi hàm ở local.
- Dữ liệu được encode bằng **Protocol Buffers** (protobuf) dạng binary, nhỏ và nhanh hơn JSON nhiều.
- Chạy trên **HTTP/2**, hỗ trợ cả **streaming**.
- Mọi thứ được định nghĩa trong file <mark>.proto</mark>, từ đó generate ra code cho cả server và client, với bất kỳ ngôn ngữ nào: Ruby, Go, Node, Java...

Nói đơn giản, file <mark>.proto</mark> là "hợp đồng" giữa 2 bên. Service Ruby và service Go chỉ cần dùng chung file này là gọi được nhau.

#### Version sử dụng
- Ruby 3.4
- gem <mark>grpc</mark> và <mark>grpc-tools</mark> 1.7x
- gem <mark>google-protobuf</mark> 4.x (được cài kèm theo <mark>grpc</mark>)

Bài này chưa cần Rails, chỉ cần một folder Ruby đơn giản để hiểu cách hoạt động.

#### Cài đặt
```sh
mkdir grpc-hello && cd grpc-hello
bundle init
bundle add grpc grpc-tools
```
Cây thư mục sau khi hoàn thành sẽ như thế này
```sh
grpc-hello
  |––Gemfile
  |––proto
       |––greeter.proto       # file định nghĩa
  |––lib
       |––greeter_pb.rb           # generate ra, không sửa tay
       |––greeter_services_pb.rb  # generate ra, không sửa tay
  |––server.rb
  |––client.rb
```

#### Viết file proto
```protobuf
// proto/greeter.proto

syntax = "proto3";

package hello;

service Greeter {
  rpc SayHello (HelloRequest) returns (HelloReply);
}

message HelloRequest {
  string name = 1;
}

message HelloReply {
  string message = 1;
}
```
- <mark>service</mark>: tương tự một controller, chứa các <mark>rpc</mark> (hàm) có thể gọi.
- <mark>message</mark>: tương tự params và response, mỗi field có type và một **số thứ tự** (<mark>= 1</mark>). Số này dùng để encode binary, đã dùng rồi thì đừng đổi.
- <mark>package hello</mark>: sẽ trở thành module <mark>Hello</mark> trong Ruby.

#### Generate code
```sh
bundle exec grpc_tools_ruby_protoc -I proto --ruby_out=lib --grpc_out=lib proto/greeter.proto
```
Lệnh này tạo ra 2 file trong <mark>lib</mark>:
- <mark>greeter_pb.rb</mark>: các class message <mark>Hello::HelloRequest</mark>, <mark>Hello::HelloReply</mark>.
- <mark>greeter_services_pb.rb</mark>: <mark>Hello::Greeter::Service</mark> (dùng cho server) và <mark>Hello::Greeter::Stub</mark> (dùng cho client).

Mỗi lần sửa file <mark>.proto</mark> thì chạy lại lệnh này.

#### Server
```ruby
# server.rb

$LOAD_PATH.unshift(File.expand_path("lib", __dir__))
require "greeter_services_pb"

class GreeterServer < Hello::Greeter::Service
  def say_hello(request, _call)
    Hello::HelloReply.new(message: "Hello #{request.name}")
  end
end

server = GRPC::RpcServer.new
server.add_http2_port("0.0.0.0:50051", :this_port_is_insecure)
server.handle(GreeterServer)
puts "gRPC server running on port 50051"
server.run_till_terminated_or_interrupted(["INT", "TERM"])
```
- Kế thừa <mark>Hello::Greeter::Service</mark>, rồi implement hàm <mark>say_hello</mark>. Tên rpc <mark>SayHello</mark> trong proto sẽ thành <mark>say_hello</mark> trong Ruby.
- <mark>request</mark> là một <mark>Hello::HelloRequest</mark>, và phải trả về một <mark>Hello::HelloReply</mark>.
- <mark>:this_port_is_insecure</mark>: không dùng TLS, chỉ dùng cho local. Production thì cần cấu hình TLS.

#### Client
```ruby
# client.rb

$LOAD_PATH.unshift(File.expand_path("lib", __dir__))
require "greeter_services_pb"

stub = Hello::Greeter::Stub.new("localhost:50051", :this_channel_is_insecure)
reply = stub.say_hello(Hello::HelloRequest.new(name: "Nolan"))

puts reply.message
```

#### Chạy thử
Mở 2 terminal
```sh
# terminal 1
bundle exec ruby server.rb

# terminal 2
bundle exec ruby client.rb
# => Hello Nolan
```

Vậy là client đã gọi hàm <mark>say_hello</mark> ở server như gọi một hàm bình thường. Bài tiếp theo chúng ta sẽ đưa gRPC vào một project Rails và làm việc với database.
